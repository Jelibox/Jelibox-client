# Jelibox - notes for Claude

Local computer-vision annotation tool (Tkinter GUI, Ultralytics YOLO). Read `README.md` for the user-facing description.

## Working rules

- Do not commit, push, tag or release unless the user asks. Local edits only by default.
- Follow `RELEASING.md` when asked to release: GitHub Flow, `feature/*` branches, one `[Unreleased]` line in `CHANGELOG.md` per user-visible change.
- Keep docs truthful about permissions and system changes: README.md, index.html and the installer messages must match what the scripts really do (see "Installer principles").
- Match the existing code: short comments, no extra abstractions.

## Layout

- `utils/Annotator.py` - entry point. No args = workspace picker, folder arg = annotation window. `config.load_workspace()` must run before `AnnotationGUI` is imported.
- `utils/` - GUI (`AnnotationGUI.py`, `WorkspacePicker.py`), training (`training.py`, run as a subprocess), export, relocate ("Move Jelibox"), `collab/` (hidden behind `JELIBOX_COLLAB=1`).
- Data per workspace: `datasetsInput/<ws>-<n>/`, `vocdataset/<ws>/`, `YOLOdataset/<ws>/labels/`, `models/<ws>/`, `configs/<ws>.json`. Images are never copied.
- Installers: `install.ps1` / `install.sh` (one-liners that download a release and unpack it), `jelibox_windows_installation.bat` / `jelibox_linux_installation.bash` (set up the environment), `tools/setup_python.ps1` / `tools/setup_python.sh` (uv + private Python), `tools/release.py`.

Tests: `tests/unit/test_web_users.py`, `tests/unit/test_web_app.py` (skip without starlette + httpx). Long work = `utils/web/jobs.py` (`POST` answers 202 with a job, the page polls `GET /api/jobs/<id>`). The editor is `utils/web/editing.py` (`Workspace(base_dir, instance)`: pictures listed like the desktop = .jpg .jpeg .png sorted; `save` checks classes / numbers, clamps to the picture, burns ZeroFill regions into the file, returns a `version` = XML date + size and refuses a stale one with `Conflict`; `ClassManager(ws, base_dir)` is cached in `editing.class_manager` and rebuilt when its class file changes) behind `utils/web/editor_api.py` (`/api/ws/<dataset>/...`) and `static/editor.js` (coordinates are ALWAYS original pixels). The Label Assistant is `utils/web/assistant.py` (context-taking copy of the desktop dispatch in `inferenceObjectDetection.build_predictor`: keep the two in step; providers come from `assistant_providers`, config-free) behind `assistant_api.py`; ONE model job at a time (`assistant.acquire`), SAM 2 references per workspace (`assistant.sam_store`; `sam2_predictor(..., store=)`), `reviewed:false` saves are not remembered. Real-model checks (SAM 2 base, YOLO-World x, an own model) ran in the scratchpad: the server needs its stdout in a FILE (an unread `PIPE` fills up with Ultralytics output and freezes it), and the first real YOLO-World run downloads CLIP (338 MB) into `ultralytics.utils.SETTINGS['weights_dir']`, a user-level folder from Ultralytics' own settings (it can point at an old install folder), NOT the Jelibox folder. Export and training: the three exporters are `utils/dataset_export.py` (`export_yolo / export_voc / export_coco(records, ...)`, `rng` for a repeatable split; the desktop's `AnnotationGUI._export_*` are one-line wrappers) and the job / process / install helpers are `utils/train_support.py` (`HeadTrainDialog` re-exports them; its `build_job` / `select_in_assistant` wrappers default `base_dir` to `config.BASE_DIR`, which tests patch). Web: `utils/web/exporting.py` + `export_api.py` (jobs; results via `Downloads` tokens, owned by the user who exported). The web never saves an export on the server (the maintainer's decision): each export is built in a scratch folder `temp/downloads/<id>/` (`Downloads.scratch`), the browser fetches it at once (`resultDialog` clicks the link by itself; a folder is zipped, then deleted; leftovers older than 6 h go at the next export) - no `Save to`, no `export_dir`, no `export dataset/` folder. The editor's zoom-out stops at `fitScale()` (the size of a freshly opened picture). Dark mode uses a white `--on-accent` on a deeper `--accent` so primary buttons read well and `utils/web/training.py` (`TrainingManager`, fake process in tests via `.command`). `yolo_train_job.on_epoch_end` only counts epochs that fired `on_train_epoch_end` first: Ultralytics' `final_eval` calls `on_fit_epoch_end` once more (epoch + 1). `export.py` imports ultralytics inside `export_model` (the path helpers must not load torch). Real checks: `python -I` ignores PYTHONIOENCODING, use `-X utf8`; after a dialog's Done/Close wait for `.overlay` to be gone before the next key press. `utils/annotation_io.py` holds the pure VOC / YOLO helpers (`write_annotations`, `sync_yolo_labels`; the desktop `file_handler` functions delegate to them) (`file_handler` re-exports them): web code and the importer use it, never `file_handler` (it pulls in tkinter + `config`).

Analyze Dataset in the web: `utils/web/analysis.py` (`payload(data, size, mode, limit)` = every number a chart needs, `Cache` keeps the last 8 `dataset_analysis.Analysis` objects under a token) behind `utils/web/analysis_api.py` (`POST /api/workspaces/<ws>/analysis` is a job, `/api/analysis/<token>/view` recalculates a size / mode / limit, `/remove-small` is a job that refuses while that workspace trains); the page is `static/analyze.js` (SVG and div charts, no library). The limit is remembered in `configs/_app.json` `small_limit` like the desktop. Move Jelibox is NOT in the web on purpose (the maintainer's decision), so the web header has no such button. Test pictures of two datasets of one workspace must have different names: the XML of a workspace is keyed by the picture's base name.

Server resources in the web (`utils/web/sysmon.py`, route `GET /api/system`, page `static/sysmon.js`; `monitorPanel()` is ONE panel for the page session, polls every 2 s only while on screen): load / RAM / disks through psutil (lazy import, null without it), CPU temperature = psutil sensors on Linux, the Windows counter `\Thermal Zone Information(*)\Temperature` (Kelvin, no admin; WMI MSAcpi needs admin and was refused) through PowerShell, GPUs through `nvidia-smi` (a fake `nvidia-smi.cmd` first on PATH tests the real path) or amdgpu sysfs on Linux. Base-model pickers in the Train window are `<select>`s (a datalist only offers what matches the typed text).

## Installer principles

- Jelibox runs on its own Python 3.12 only: uv downloads it into `<install>/.python`, the virtual environment is `<install>/venv` (Windows) or `<install>/jelibox` (Linux). There is no system-Python fallback and no `JELIBOX_PYTHON=system`.
- uv is looked up (`JELIBOX_UV`, PATH, uv's default install folders) and installed with the official installer only when missing: Windows `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`, Linux/macOS `curl -LsSf https://astral.sh/uv/install.sh | sh`.
- Never put Python on `PATH`, never register it with Windows (`UV_PYTHON_INSTALL_REGISTRY=0`, `--no-bin`), never `activate` the environment: call `<venv>\Scripts\python.exe` / `<venv>/bin/python` by path.
- Elevation: nothing runs as administrator/sudo by default. Windows elevates only `VC_redist.x64.exe` (`:INSTALL_VCREDIST`), and only when the runtime is missing. Linux uses `sudo` only to install libGL/GLib when `import cv2` fails.
- GPU: the installers ask whether the machine has a discrete NVIDIA GPU (detection is only the default). The answer travels as `JELIBOX_GPU=nvidia|cpu` (`install.ps1`/`install.sh` ask first, the `.bat`/`.bash` ask only when it is unset). NVIDIA installs PyTorch from `whl/cu121`, CPU from `whl/cpu` (never PyPI's default Linux wheel, which is CUDA).
- App + web or app only: every install and update asks (`install.ps1` / `install.sh`, the `.bat` / `.bash` ask only when `JELIBOX_WEB=yes|no` is unset; Enter = the last answer, kept in `<install>/.jelibox-web`, else yes). The web packages are in `requirements-web.txt` (starlette, uvicorn, python-multipart, httpx), installed only for yes. Yes also runs `tools/web_service.ps1 -Action install` (Windows: hidden `venv\Scripts\pythonw.exe utils\server.py` from a shortcut "Jelibox Web" in the user's Startup folder, at SIGN IN not at boot; `JELIBOX_STARTUP_DIR` redirects it in tests) or `tools/web_service.sh install` (systemd USER unit `jelibox-web.service`, `loginctl enable-linger` without sudo when the system allows it, one `sudo loginctl enable-linger` otherwise, declining only means "while signed in"; `JELIBOX_SYSTEMD_DIR` / `JELIBOX_WEB_WAIT` for tests); no runs `remove`. An update stops the old server BEFORE files and packages change (install.ps1 / install.sh / the installer scripts all call `stop`). Nothing touches the firewall: the scripts only print the command (Windows `New-NetFirewallRule` as administrator, ufw / firewalld on Linux). Started without a console the server logs to `temp/server.log` (`server.log_to_file_without_console`; pythonw has no stdout and uvicorn would crash). `tests/repo/test_web_install.py` covers all of it with a fake systemctl / loginctl and a temporary Startup folder; the full `.bat` / `.bash` run (torch download) is not in the suite.
- `jelibox_windows_installation.bat` must keep CRLF line endings (tests check this); `*.sh` / `*.bash` must stay LF.

## Modes (front menu)

- Four modes, chosen on the picker's front menu and stored app-wide (`configs/_app.json` key `mode`, `utils/assistant_modes.py`): YOLO-World (original; provider `yolo_world` or `custom_model`), LocateAnything (`locate_anything`), Custom Model (called `custom_head` in the code and the config), SAM 2 Dynamic (`sam2_dynamic`). Per-workspace settings live in `configs/<ws>.json` under `label_assistant` (`utils/workspace_config.py`).
- `utils/inferenceObjectDetection.py` builds the predictor for the current mode; `G` / the Infer window (`AnnotationGUI.show_infer_dialog`, choice kept in `infer_scope`, default single image) and Auto-annotate all (`utils/auto_annotate.py`, GUI in `utils/AutoAnnotateDialog.py`) share it. Providers are config-free functions in `utils/assistant_providers.py`.
- Never load the 3B LocateAnything model in tests or scripts: tests fake the predictor; check imports with the processor/tokenizer only. Keep torch / transformers imports lazy (a test enforces it). Its remote code is pinned (`MODEL_REVISION`); change it only after reading the diff.
- Original mode can also use any Ultralytics model chosen with **Browse custom model** (`custom_model` block: path + class_map). A browsed model maps its class NAMES to workspace classes; the workspace's own `modelAssistant.pt` still maps by index (`inferenceObjectDetection.custom_model_file`, `build_predictor`).
- Workspace classes: use `inf.current_classes()` (live `class_manager`), never `config.CLASSLIST` in code that runs after the window opened. `CLASSLIST` is a snapshot from `load_workspace`; filtering predictions with it made Auto-annotate label nothing when a class was added later.
- Package limits live in `requirements.txt` only (`ultralytics>=8.4.68`, `transformers==4.57.6`, `huggingface_hub<1.0`); PyTorch is chosen by the installers. One environment serves all modes.
- Custom Model (code: custom head) = frozen detector (class ids are a setting) + trained head; sources it was ported from are in `TOBEADDED/` (kept as received, skipped by the hygiene test).
- Train in this mode (`AnnotationGUI._train_head` -> `HeadTrainDialog`) has two kinds, chosen by `kind_var` at the top of its window. Its DATA card shows `utils/SplitBar.py` (the Train / Valid / Test bar shared with Export Dataset; `head_data.split_three`: by position, or mixed with `shuffle`) and, for the full kind, a **background** box: `head_data.scan_labels` returns (pictures with boxes, pictures whose label file is EMPTY = saved with nothing in them, never those without a label file) and `job["background"]` splits and copies the empty ones too (empty label written; the MIN_LABELLED check counts boxes pictures only; `start` carries `background_images`); the head kind never uses them for the full kind and the old validation box for the head kind; the job carries `val_fraction`, `test_fraction`, `shuffle`, `split_seed`; `yolo_train_job.prepare` (`prepare_dataset` is its old 5-tuple wrapper) copies a test part aside, names it in `data.yaml`, emits `prepare` events (done/total/text, the window shows them as a bar before the first epoch) and `_evaluate_test` scores `best.pt` on it at the end (`test_map50` ... in `done`; a failure is only logged). **Full YOLO training** runs `python -m utils.yolo_train_job <job.json>` (`utils/yolo_train_job.py`: `prepare_dataset` copies the labelled images into a scratch train/val tree inside `models/<ws>/yolo_run/dataset` with the positional split, `YOLO.train` with `plots=False`, callbacks `on_train_start` / `on_fit_epoch_end` print `epoch` events with `box_loss`, `cls_loss`, `dfl_loss`, `precision`, `recall`, `map50`, `map5095`, `fitness`, `best`; the scratch copy is removed in `finally` and by the window), and installs `train_run/weights/best.pt` as `models/<ws>/modelAssistant.pt` (old one -> `modelAssistant.prev.pt`) with the workspace provider set to `custom_model` (YOLO-World mode uses it; the app mode is NOT switched). `device` is chosen by the job (`0` / `"cpu"`; `0` is a valid value, so never test it with `or`). The window shows a `ttk.Treeview` table per epoch for both kinds (`HEAD_COLUMNS` / `YOLO_COLUMNS`); `default_command(job_path)` picks the module from the job's `kind`. **Finish early** = the window writes `job["stop_file"]` (`<run folder>/finish_early.flag`, `stop_file_for`); `yolo_train_job` sees it on the next batch (`on_train_batch_end`, also `on_fit_epoch_end`) and sets `trainer.stop = True` (Ultralytics leaves the batch loop between batches, validates, saves, then `final_eval()`), `head_train` checks `should_stop()` after every batch and still evaluates and saves the interrupted epoch; both end with a `done` event with `stopped: true`. The window removes the flag before a launch and after the end. **Stop now** still kills the process (`TrainProcess.stop`). The progress window follows its content size (`geometry("")`): a fixed height once cut the buttons off - `buttons_fit` in the tests checks they are visible. Fakes: `FAKE_TRAINER` / `FAKE_YOLO_TRAINER` scripts in `tests/gui/test_modes_gui.py`, a fake `YOLO` class in `tests/unit/test_yolo_train_job.py`. **Head only** trains the head, not a YOLO model: `utils/HeadTrainDialog.py` (setup + progress window) runs `python -m utils.head_train <job.json>` as a subprocess (`@@ {json}` event lines on stdout), `utils/head_data.py` is the torch-free data side (pairing, position-based split, taps per detector family). It installs `models/<ws>/head_best.pt` and points `custom_head` at it. Tests fake the detector; the real-detector run is done by hand (CPU, minutes per epoch).
- SAM 2 Dynamic (`utils/sam2_dynamic.py`): `ReferenceStore` keeps ONE record per image path (replaced whole on every `save_current`, so an annotation can never be a reference twice); `Sam2Engine.build` assembles the predictor's memory bank from the store (one entry per image, encodings cached per image + boxes + file stamp) and never appends blindly. One object slot per workspace class (`max_obj_num = len(classes)`, obj id = class position); a reference is given as ONE mask per class holding ALL its objects (`reference_masks`: polygons filled exactly, boxes first refined to silhouettes by `Sam2Engine._boxes_refiner` = SAM 2 in its normal one-image mode, rectangles only as a fallback; plain rectangles taught the background and merged/loosened results in a boots test) - SAM 2 remembers unmarked look-alikes as background, so a single box per class made it skip the second worker (measured). Polygon mode uses polygon items only, box mode uses boxes (+ polygon bounding boxes) - `ReferenceStore.select(..., polygon)`. The predictor must be created with `conf=0` (it drops objects scoring 0 and our `min_score` decides); output row i is slot `list(obj_idx_set)[boxes.cls[i]]`. Images whose annotations came from the assistant and were not edited (`AnnotationGUI._assist_unreviewed`) are not stored. Tests fake the predictor; the real run (`sam2.1_t.pt`, CPU, seconds) is done by hand.
- Add Workspace / the "+" on a workspace (`WorkspacePickerApp._open_add_workspace_dialog`) is the only way to bring a dataset in (there is no Import Dataset button): on Browse it runs `dataset_import.scan_dataset_folder` + `scan_classes` (the summary and the amber "SKIPPED" warning are shown before Create and follow the typed workspace name), then Create calls `dataset_import.import_dataset(folder, ws, prefix, progress_cb, classes)`. A workspace that already has classes is "locked": other classes are skipped and counted (`result["skipped"]`) and its config is never changed; a new one gets the typed classes first, then those found. YOLO labels are regenerated from the parsed objects with the workspace class list, never copied. **Videos**: `scan_dataset_folder` also returns `videos` (`VIDEO_EXTENSIONS`); when there are some the dialog shows the **Skip frames** box (`skip_var`, default `DEFAULT_SKIP_FRAMES` = 10, estimate from `probe_videos` + `frames_to_save`) and `import_dataset(..., skip_frames)` saves every N-th frame with `extract_frames` (cv2 `grab()` for skipped frames, JPEG via `imencode` + `tofile`, names `<video>_f<frame>` or `<prefix><n>` continuing after the images; a folder of only videos is valid, an unreadable one goes to `result["video_errors"]`, nothing readable at all raises and removes the empty instance). The dialog form is a `ScrollBody` with Cancel / Create outside it, and its label wrap is `width - 70` (the scrollbar takes room). `workspace_manager.create_workspace_instance` (images only, flat folder) is no longer used by the window.
- Export Dataset has a **Save to** row (`AnnotationGUI.show_export_dataset_dialog`; remembered in `configs/_app.json` key `export_dir`; a remembered or chosen folder that no longer exists, e.g. an unplugged drive, falls back to the default folder - at open (the setting is kept) and again at export time). `utils/export.py` holds the pure helpers: `plan_export_target` (no folder chosen = the old `export dataset/<ws>` folder, replaced each time; a chosen folder = a new `<ws>-v<N>` inside it, `next_version_name` counts on from the highest existing one, never deleting anything), `check_destination` (writable + free space for the images) and `files_size`. The export runs on a worker thread that reports with `root.after`, which only works while the Tk main loop runs: GUI tests start it from inside `root.mainloop()` (`_export_and_wait`), pumping with `update()` raises "main thread is not in main loop". The worker must not assign to a variable of the enclosing function (an earlier `target = ...` made it local and the export died with UnboundLocalError).
- Export Dataset is `utils/ExportDatasetDialog.py` (`AnnotationGUI.show_export_dataset_dialog` only opens it): Format + Save to (rules above), split bar (`split_counts` rounds like the exporters), **Preprocessing** (`utils/export_preprocess.py`: `Preprocess(auto_orient, resize)`; `original(path)` returns the picture to write instead of copying the file, `post` goes to `Augmenter(post=...)` and chains the augmentation transform with `ResizeTransform`; labels follow through `yolo_label_text` / `voc_xml_write` / `coco_annotation` with the same matrix), and the **Augmentation** picker. The three `_export_*_dataset` take `augment` and `preprocess`; `Augmenter.keeps_original(split)` False = train originals are not written. The picker is `utils/AugmentationPanel.py` (Tk) over `utils/augment_catalog.py` (tiles, previews, `to_config`: `outputs` = pictures per training image, `copies = outputs - 1` when the original is kept) and `utils/augment_sample.py` (preview picture: first image of the workspace, or `preview.image` in `configs/<ws>.json`, relative to the Jelibox folder, falling back when the file is gone). `AugmentChoice` is the Train windows' button + summary: `build_yolo_job(augment=config_to_dict(...))` puts it in the job and `yolo_train_job.prepare_dataset` writes the augmented copies of the train part, and of val / test only when the config's `splits` names them (the picker's **Also augment** row; training is always in it). Tiles Ultralytics already does while training (`ultralytics` key in the catalog: flip, rotate, shear, hue, saturation, brightness) are greyed out with a note when `training=True`. GUI tests restore label files another test left (`_label_the_test_images`), or later tests see stray annotations.
- Analyze Dataset (`utils/dataset_analysis.py` numbers, `utils/DatasetAnalysisDialog.py` matplotlib window): the picker keeps `selected` (workspace name without index, highlighted row) and enables the **Analyze** button from it. Data comes only from `vocdataset/<ws>/*.xml` (image size is in the file; polygons count through their bounding box; an XML without a matching image is ignored, one without a size is left out of the resize simulation). Resize is calculated (`view(data, size, mode)`: letterbox = size / longest side, stretch = per axis), never done on disk. Objects with a side under the limit (`SMALL_LIMIT` = 32 px by default; the "Small object limit" box in the window changes it, 1-1024, remembered in `configs/_app.json` key `small_limit`) raise a warning strip in the window; the charts, the table and Remove all use `self.limit`. matplotlib is imported inside the window only (`Figure` + `FigureCanvasTkAgg`, no pyplot); the GUI test skips without it. `da.remove_small` (the strip's **Remove these objects** button, after an `askyesno` warning that says to back up first; default answer No) rewrites the flagged XML files without those objects and regenerates their YOLO labels with the workspace class list through `file_handler._yolo_lines_from_annotations` (imported lazily: it pulls in `config`, so its test lives in the integration group); objects of an image whose size is unknown are only removed in the original-size view, and then no YOLO label is written. Reading the files reports progress (`analyze(..., progress_cb)`), shown by `utils/progress_popup.py` (also used by the picker's delete popups). Screenshots of it: the app is DPI-unaware, so do not call `SetProcessDPIAware` in the script (matplotlib then sizes the figure 1.25x too large); save the figures with `fig.savefig` instead.
- Dialogs taller than the screen use `utils/dialog_scroll.py` (`ScrollBody`): header and footer stay, the body scrolls.

```bash
python tests/run.py                    # everything: repo, unit, integration, GUI
python tests/run.py --only repo,unit   # what CI runs (also runs on Linux and Windows) with only pillow, numpy and opencv-python-headless installed:
```

Real-environment check: build a scratch Python 3.12 venv with uv (torch from the CPU index, then `-r requirements.txt`) and run `tests/run.py` with its python. `JELIBOX_TEST_DOWNLOAD=1` also runs the custom-head test that downloads a 5 MB detector.

## Gotchas

- `jelibox-local.zip` (scratchpad) is a snapshot: rebuild it after every change you want the user to install. A stale archive once made a fixed bug look unfixed. The installed copy at `%USERPROFILE%\Jelibox` is also a snapshot, so check what it contains before diagnosing.
- Python 3.10 aborts (`Tcl_AsyncDelete`, "main thread is not in main loop") when a Tk variable is garbage-collected on a non-main thread. Avoid threads in dialog code (`subprocess.run(capture_output=True)` starts reader threads too; `HeadTrainDialog` polls a log file instead) and keep the `<Destroy>` -> `gc.collect` hook in `ModeDialogs._Dialog`.
- The Train button of every mode except Custom Model and SAM 2 Dynamic (`AnnotationGUI.start_training`) opens the SAME window as Custom Model's full training: `HeadTrainDialog(..., full_only=True, on_start=...)` (no head choice; the old `TrainingConfigDialog` is gone). The setup fields are identical in every mode (base model + Browse, Continue - ticked by default when a trained model exists, size, epochs, batch, lr, weight decay, freeze, `SplitBar` default 70 / 20 / 10, background box, `AugmentChoice`); `build_yolo_job` makes the job, init = the existing `modelAssistant.pt` when Continue is on, else the chosen base. The window releases its grab once the process started (`on_start` sets `state.training_process` / `state.training_running`, `on_done` clears them; a second Train is refused meanwhile). No terminal is opened; `utils/training.py` and `train_subprocess.py` are not used by the GUI (training.py is still runnable by hand; its `device` is `0` with a GPU, `"cpu"` without).
- A training process must never outlive Jelibox: `TrainProcess` binds the worker to Jelibox with `utils/process_guard.py` (Windows job object with kill-on-close, Linux `PR_SET_PDEATHSIG`; a test kills the parent and checks the child dies) and `process_guard.claim` / `running_training` / `release` keep `temp/training.lock` so only one training runs at a time (a lock whose pid is dead is stale). `AnnotationGUI.close_main_gui` (also the window's X, Escape, the back button) asks first when `state.training_process` is alive and calls `HeadTrainDialog.stop_and_finalize` (stop, then install the best model).
- Picture counts per workspace live in `configs/_stats.json` (`utils/workspace_counts.py`: images per folder, labelled, background, boxes per class). NOTHING counts by itself: the Train windows read them (`get_or_empty`; `HeadTrainDialog(counts=...)`, `counted: None` = never counted, shown as such, the MIN_LABELLED check is skipped and training still starts because `yolo_train_job.prepare` reads the real files), only the picker's **Refresh** (`recount_all`, drops vanished workspaces) and the Train window's **Refresh** (`HeadTrainDialog._refresh_counts`, counts on a thread that touches no Tk) write them. Do not add automatic recounts (a 10k+ picture workspace takes seconds to minutes). `head_data.scan_labels` also keeps `.label_cache.json` (file size + date) beside the labels folder for the training process.
- The header shrinks in steps (`AnnotationGUI.HEADER_LEVELS`: tighter buttons, then no brand text, then icons with tooltips), measured with `_header_need`, so it fits a 12-inch screen (about 1280 px logical). Header buttons are made with `_hbtn`; change a label with `_set_hbtn_text`, never `config(text=...)`. Tests find them by their full label (`btn._jb['full']`).
- GUI checks by hand: copy the installed app to the scratchpad, drive the real window, screenshot with `SetProcessDPIAware()` (the user's display is 125%); `root.deiconify()` first or transient dialogs stay hidden. Never load the 3B model; a real head-training run on CPU takes minutes per epoch.
- The Bash tool mangles backslashes and quotes in heredocs: write edit scripts with the Write tool (UTF-8, CRLF-aware) instead.

- The one-line installers download from GitHub, not from the folder they sit in. Local changes are only installed through `JELIBOX_ARCHIVE`.
- `releases/latest` is what `install.ps1` installs by default; changes on `main` reach users only after a release is cut.
- `tests/repo/test_python_setup.py` checks installer wiring by reading the scripts as text; update it together with the scripts.
- `tools/setup_python.*` tests use a fake uv (`JELIBOX_UV`); the real uv branch was verified by hand, not in the suite.
